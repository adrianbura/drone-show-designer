# RGB structure audit (read-only, `rgb-structure-v1`)

Generated by `bun scripts/auditRgbStructure.ts [--generic] <zip> <out.json> <sha256>`; SHA-256 verified before decoding; source samples asserted unchanged. Each show uses only its own forensic segments — no cross-show interval equivalence. Recipe: UNKNOWN.

Metrics (`src/lib/import/essp/native/rgbStructure.ts`):
- **Groups (A):** drones with an identical exact RGB sequence over the interval; groups need ≥3 drones. `AMBIGUOUS` when no group or >50% of drones are ungrouped.
- **Temporal (B):** `STATIC` only when every drone is constant. Period is chosen on the first half of the fleet-mean brightness (autocorrelation ≥0.8 after leaving the zero-lag lobe, ≥3 cycles). `PULSATION_SUPPORTED` needs held-out second-half correlation ≥0.7, amplitude σ≥8 and median in-phase correlation ≥0.9. `WAVE_SUPPORTED` needs a linear phase-lag vs position fit on even drones with held-out R² ≥0.8 on odd drones. Otherwise `PERIODIC_UNVALIDATED` / `NONPERIODIC_OR_UNKNOWN`. Intervals >1200 RGB ticks: `TOO_LONG`.
- **Reconstruction (C):** playback reference is always the exact source. Candidate models (shared color per tick, fixed color per drone, exact groups + ungrouped fallback) are scored by mean/max byte error; a model is accepted only with max error ≤2, else `UNKNOWN`.
